This guide walks you through running a real payment form in the browser without preparing your own Stripe account or API keys. Every step is verified, and finishing it ends with an actual successful payment in Stripe test mode.

## Try it first

Before writing code, you can try the live demo in CodeSandbox (Stripe test mode, no API keys needed).

[![Edit in CodeSandbox](https://codesandbox.io/static/img/play-codesandbox.svg)](https://codesandbox.io/p/devbox/github/hideokamoto/stripe-pwa-elements/tree/main/examples/codesandbox)

The demo covers three components:

- `<stripe-card-element>` (card input with a Payment Intent confirm flow)
- `<stripe-address-element>` (address form)
- `<stripe-express-checkout-element>` (Apple Pay / Google Pay / Link, device-dependent)

There is no `<stripe-payment-element>` demo yet.

## How the demo API works

The steps in this guide use a demo API provided by the documentation site. It creates Payment Intents and Checkout Sessions on a Stripe test-mode account, so you can try the full payment flow without your own Stripe account.

| Endpoint | Method and body | Returns |
| --- | --- | --- |
| `/api/config` | GET | `{ publishableKey }` |
| `/api/create-payment-intent` | POST `{ "currency": "jpy" }` | `{ clientSecret }` |
| `/api/create-checkout-session` | POST `{ "currency": "jpy" }` | `{ clientSecret }` |

The base URL is `https://stripe-pwa-elements-docs.wp-kyoto.workers.dev`. Supported currencies are `usd`, `jpy`, `eur`, `gbp`, and `aud`, with the amount fixed server-side at 1,000. Browsers can only call it from CORS-allowed origins: `localhost` ports `3000`, `4321`, and `5173`, plus previews such as `*.csb.app` and `*.stackblitz.io`.

The publishable key also comes from the demo API. A clientSecret is bound to the Stripe account that created it, so it must be paired with a publishable key from the same account.

Note that the demo API is for trying these steps only. In production, create the Payment Intent or Checkout Session on your own server and pass its clientSecret to the browser. See [Payment flows](/en/guides/payment-flows/) for the full picture.

### 4. Replace src/main.ts

Import the component you use from `dist/components`. The import itself registers the custom element.

```ts
import 'stripe-pwa-elements/dist/components/stripe-card-element';

const API = 'https://stripe-pwa-elements-docs.wp-kyoto.workers.dev/api';

const log = (message: string, detail?: unknown) => {
  const out = document.querySelector<HTMLPreElement>('#log')!;
  out.textContent += detail === undefined ? `${message}\n` : `${message}\n${JSON.stringify(detail, null, 2)}\n`;
};

// Fetch the publishable key and a clientSecret from the demo API
const { publishableKey } = await (await fetch(`${API}/config`)).json();
const { clientSecret } = await (
  await fetch(`${API}/create-payment-intent`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ currency: 'jpy' }),
  })
).json();

// Create the element and set its attributes
const el = document.createElement('stripe-card-element');
el.setAttribute('publishable-key', publishableKey);
el.setAttribute('intent-client-secret', clientSecret);
el.setAttribute('button-label', 'Pay now');

// Subscribe to events
el.addEventListener('stripeLoaded', () => log('event: stripeLoaded'));
el.addEventListener('formSubmit', () => log('event: formSubmit'));
el.addEventListener('defaultFormSubmitResult', event => {
  const detail = (event as CustomEvent).detail;
  if (detail instanceof Error) {
    log('payment failed', { message: detail.message });
  } else {
    log('payment result', detail);
  }
});

document.querySelector<HTMLDivElement>('#checkout')!.appendChild(el);
```

### 5. Run it and pay

```bash
npm run dev
```

Open `http://localhost:5173` and the card form appears. Enter card number `4242 4242 4242 4242`, any future expiry, and any CVC, then press **Pay now**. When the logged `payment result` shows `status: succeeded`, the payment is complete.

In HonoX, load the component on the client only, inside an island. The package's modules touch browser-only APIs such as `customElements`, so a static import during SSR throws. A dynamic import inside `useEffect` avoids that.

### 1. Create the HonoX project

```bash
npm create hono@latest stripe-honox -- --template x-basic --install --pm npm
cd stripe-honox
```

### 2. Add stripe-pwa-elements

```bash
npm i stripe-pwa-elements
```

### 3. Create the island

Create `app/islands/payment-form.tsx`.

```tsx
import { useEffect, useRef, useState } from 'hono/jsx';

const API = 'https://stripe-pwa-elements-docs.wp-kyoto.workers.dev/api';

export default function PaymentForm() {
  const containerRef = useRef<HTMLDivElement>(null);
  const [logs, setLogs] = useState<string[]>([]);

  useEffect(() => {
    let cancelled = false;
    const appendLog = (message: string) => {
      if (!cancelled) setLogs(prev => [...prev, message]);
    };

    (async () => {
      // Load on the client only — the module touches browser-only APIs (customElements)
      await import('stripe-pwa-elements/dist/components/stripe-card-element');

      const { publishableKey } = await (await fetch(`${API}/config`)).json();
      const { clientSecret } = await (
        await fetch(`${API}/create-payment-intent`, {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({ currency: 'jpy' }),
        })
      ).json();

      if (cancelled || !containerRef.current) return;

      const el = document.createElement('stripe-card-element');
      el.setAttribute('publishable-key', publishableKey);
      el.setAttribute('intent-client-secret', clientSecret);
      el.setAttribute('button-label', 'Pay now');
      el.addEventListener('stripeLoaded', () => appendLog('event: stripeLoaded'));
      el.addEventListener('formSubmit', () => appendLog('event: formSubmit'));
      el.addEventListener('defaultFormSubmitResult', event => {
        const detail = (event as CustomEvent).detail;
        appendLog(detail instanceof Error ? `payment failed: ${detail.message}` : `payment status: ${detail.paymentIntent?.status}`);
      });
      containerRef.current.appendChild(el);
    })();

    return () => {
      cancelled = true;
    };
  }, []);

  return (
    <div class="mx-auto max-w-xl text-left">
      <div ref={containerRef}></div>
      <pre class="mt-4 whitespace-pre-wrap text-xs">{logs.join('\n')}</pre>
    </div>
  );
}
```

## Troubleshooting

- `Origin is not allowed` — check that your dev server runs on a port allowed by the demo API's CORS policy (`3000`, `4321`, or `5173`).
- `Failed to fetch dynamically imported module` — check whether you are using the lazy loader `stripe-pwa-elements/loader`. In bundler environments, switch to static imports from `dist/components` as described in [Bundler integration](/en/guides/bundler-integration/).
- The component shell renders but the card inputs never appear — check your version. In v4.0.0, per-component `dist/components` imports never mounted the inner Stripe element. This is fixed in `stripe-pwa-elements@4.0.1` and later.
- Wallet buttons don't render — check device support. `<stripe-express-checkout-element>`'s Apple Pay, Google Pay, and Link buttons only render on capable browsers and devices.
